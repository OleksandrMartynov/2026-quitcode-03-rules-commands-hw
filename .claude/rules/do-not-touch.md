# Захищені зони репозиторію

## Контекст

`app/src/core/` належить платформній команді — той самий core працює в усіх
клієнтських воркерах агенції, і зміни в ньому йдуть окремим PR через рев'ю цієї
команди. `app/scripts/`, `materials/`, `.coderabbit.yaml` і `.github/` — це
інструменти перевірки й вихідні дані: код, який змінює власну перевірку,
перевіркою більше не є.

## Правило

### Ці шляхи не редагуються

| Шлях | Що це |
|---|---|
| `app/src/core/**` | ядро платформи, зокрема `types.ts`, `http.ts`, `config.ts`, `parse.ts`, `log.ts` і їхні тести |
| `app/scripts/**` | `check-rules.mjs` і `core.lock.json` — перевірка правил |
| `materials/**` | архітектурна записка, лог інциденту, A/B-запит |
| `.coderabbit.yaml` | конфігурація рев'ю |
| `.github/**` | шаблон PR і робочі процеси |

Не редагуй, не створюй і не видаляй файли за цими шляхами. Це стосується й
«адитивних» змін: додати одне поле в інтерфейс, додати один файл поруч, додати
рядок у кінець — така сама заборона, як переписати модуль.

Не обходь заборону іншим інструментом: ні редактором, ні `sed -i`, ні `cat >`,
ні `python -c`, ні застосуванням патча.

### Окремо: не підганяй перевірку

Не запускай `node scripts/check-rules.mjs --write-lock`.
Цей режим перезаписує `app/scripts/core.lock.json` поточними хешами ядра — після
нього `check:rules` показує `core-untouched 0` навіть тоді, коли ядро змінили.
Це не виправлення, а приховування сліду.

### Що робити, коли задача впирається в захищену зону

Зупинись і напиши людині:

1. який саме файл і рядок треба змінити (наприклад, `app/src/core/types.ts`,
   інтерфейс `Lead`);
2. яку саме зміну (наприклад, додати поле `utmCampaign?: string`);
3. чому без неї задача не виконується (наприклад: фікстури тестів типізовані
   `const lead: Lead`, а `tsconfig` має `strict: true`, тож `npm run typecheck`
   впаде);
4. що вже зроблено в незахищених шляхах і що лишилось після зміни в core.

Потім **чекай відповіді**. Не починай зміну в core й не обирай обхідний шлях,
який ламає інші правила (`any`, дублювання типу в `integrations/`, власна копія
функції ядра).

Незавершена задача з описаною причиною — правильний результат.
Задача, «завершена» через зміну ядра, — зламана домовленість команди.

## Як перевірити

```bash
git diff --stat upstream/main...HEAD -- app/src/core app/scripts materials .coderabbit.yaml .github
git status --short -- app/src/core app/scripts materials .coderabbit.yaml .github
```

Обидві команди мають дати **порожній вивід**. Будь-який рядок — порушення.

Додатково: `cd app && npm run check:rules` → у розділі `by rule` рядок
`core-untouched  0`. Якщо там не нуль — ядро змінене або `core.lock.json` не
збігається з файлами.
