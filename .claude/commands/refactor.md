# Refactor

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає конкретного файлу — ціль вказана в повідомленні одразу
після назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. **Перевір, що ціль дозволена.** Звір шлях із `.claude/rules/do-not-touch.md`.
   Якщо файл у захищеній зоні — зупинись і скажи про це; не рефактори його.

2. **Зніми стан ДО** і збережи дослівно — ці числа підуть у звіт.
   Три команди, **кожну окремо**, і запиши результат кожної: якщо одна впала,
   решта все одно мають бути виконані, інакше «до» буде неповним.
   ```
   cd app && npm test
   cd app && npm run typecheck
   cd app && npm run check:rules
   ```
   З виводу `check:rules` випиши рядок `TOTAL:` і рядок цільового файлу в розділі
   `by file`, а також кожне порушення цього файлу з розділу зверху (правило + рядок).

3. **Прочитай тести цільового файлу** — файл `<шлях без розширення>.test.ts`
   поруч (для `app/src/integrations/sheets-append.ts` це
   `app/src/integrations/sheets-append.test.ts`). Вони і є визначенням поведінки,
   яку не можна змінювати: URL, тіло запиту, тексти помилок. Випиши ці зафіксовані
   значення перед тим, як щось міняти.
   **Якщо такого файлу немає — зупинись** (див. Stop): підтвердити незмінність
   поведінки нічим.

4. **Перепиши файл під конвенції.** Що саме вимагається — у
   `.claude/rules/conventions.md`; сюди правила не переписуй, звіряйся з файлом.
   Порушення, які показав `check:rules`, закривай по одному.
   Дозволено міняти **лише цільовий файл**. Якщо для цього доводиться правити ще
   якийсь файл — зупинись (див. Stop).

5. **Зніми стан ПІСЛЯ** тими самими трьома командами, знову кожну окремо. Порівняй:
   - `npm test` — те саме число зелених, **жодного червоного**;
   - `npm run typecheck` — зелений і до, і після;
   - `check:rules` — порушень цільового файлу стало менше або нуль, і **жодного
     нового порушення в інших файлах**.

   Окремо перевір **приховані зміни поведінки, яких тести не бачать**: заміна
   прямого виклику на функцію ядра приносить із собою її типові параметри.
   Найчастіший випадок — `fetch` → `postJson`: у `postJson` за замовчуванням
   `retries: 2`, тобто до трьох запитів там, де раніше був рівно один.
   Якщо типові значення не збігаються зі старою поведінкою — **передай їх явно**
   (`{ retries: 0 }`) і додай тест, який це фіксує.

6. **Звіт:** таблиця «до → після» для `TOTAL`, для цільового файлу й для кожного
   правила, яке було порушене; і окремо — перелік того, що **не** змінилось у
   поведінці, з посиланням на твердження тестів із кроку 3.

## Acceptance criteria

- [ ] Змінено рівно один файл — той, що в цілі. `git status --short` не показує
      інших змінених файлів.
- [ ] `cd app && npm test` зелений, і кількість тестів **не зменшилась** проти кроку 2.
- [ ] Жодне твердження в жодному `*.test.ts` не змінене, не видалене й не пом'якшене:
      `git diff HEAD -- 'app/**/*.test.ts'` — порожній.
      Саме `HEAD`, а не `git diff`: без `HEAD` зміна, яку вже додали через
      `git add`, у вивід не потрапляє.
- [ ] `cd app && npm run check:rules`: порушень цільового файлу стало менше
      (або їх і до початку було нуль — тоді так і напиши);
      у жодному іншому файлі число порушень не зросло.
- [ ] **Кожне закрите порушення закрите переходом на функцію ядра, а не видаленням
      рядка.** Для кожного — рядок звіту «було `<код>` → стало `<код>`».
      Видалити `console.error` замість того, щоб провести його через `log`, —
      це не рефакторинг, а втрата поведінки.
- [ ] `cd app && npm run typecheck` — зелений і до, і після; обидва результати в звіті.
- [ ] **Типові параметри функцій ядра звірені зі старою поведінкою.** Якщо
      заміна принесла інші значення за замовчуванням (кількість повторів,
      таймаут, заголовки) — вони передані явно, і на це є тест.
- [ ] У звіті **дослівно процитовано** блок `TOTAL: N violation(s)` до і після —
      два блоки, скопійовані з виводу.
- [ ] Жоден файл із `.claude/rules/do-not-touch.md` не змінений.
      `check-rules.mjs --write-lock` не запускався.

## Stop

Зупинись і спитай людину, **не роблячи зміни**, якщо справджується будь-що з цього:

- щоб привести файл до конвенцій, треба змінити ще якийсь файл (зокрема тест,
  сусідній модуль або щось у `app/src/core/`);
- тест після рефакторингу червоний, і щоб він позеленів, треба змінити його
  твердження — **твердження не редагуй**: червоний тест означає, що поведінка
  змінилась, тобто рефакторинг неправильний;
- цільовий файл лежить у захищеній зоні;
- для виправлення потрібна нова залежність;
- поруч із цільовим файлом **немає** `*.test.ts` (напр. `app/src/sync/state.ts`,
  `app/src/integrations/index.ts`): незмінність поведінки нічим підтвердити,
  а тест пишеться окремою задачею.

У кожному з цих випадків опиши, що саме заблокувало, і чекай відповіді.

**Перед тим як питати — поверни дерево в чистий стан:** `git checkout -- <ціль>`,
і переконайся, що `cd app && npm test` знову зелений. Зупинка не означає
«лишити напіврефакторений файл і червоний тест»: у PR тести мають бути зеленими.
Рефакторинг «майже без зміни поведінки» не здають: або поведінка та сама,
або це вже інша задача.
