# Generate integration

**Ціль:** $ARGUMENTS
(Якщо в рядку вище немає назви сервісу — ціль вказана в повідомленні одразу після
назви команди. Немає й там — спитай і зупинись.)

## Кроки

1. **Прочитай зразок і контракт**, перш ніж писати:
   - `app/src/integrations/slack-notify.ts` — канонічна реалізація (іменований
     експорт, ранній вихід на `readEnv`, `postJson`, `log`);
   - `app/src/integrations/slack-notify.test.ts` — форма тестів;
   - `app/src/integrations/index.ts` — реєстр;
   - `app/src/core/types.ts` — контракт `Integration` і тип `Lead`.

2. **Визнач ім'я.** `<kebab-name>` з назви сервісу; поле `name` модуля дорівнює
   імені файлу. Визнач, які змінні середовища потрібні, і перелічи їх у
   `requiredEnv` **іменами** — значень не вписуй нікуди.

3. **Визнач тип системи** і скажи про це в підсумку:
   - **сповіщення** (Slack, Telegram, месенджери) — діє правило мінімізації даних;
   - **система обліку** (таблиця, CRM) — повні дані дозволені.
   Що саме дозволено в кожному випадку — у `.claude/rules/conventions.md`.

   **За замовчуванням — сповіщення.** «Система обліку» — це лише сервіс, який
   зберігає лід як запис (таблиця, CRM). Якщо сервіс не є таким явно, вважай його
   сповіщенням: четвертий тест обов'язковий, email і телефон у тіло не йдуть.
   Класифікацію «система обліку» обґрунтуй у підсумку окремим рядком і чекай
   підтвердження людини, перш ніж класти в тіло повні дані.

4. **Створи `app/src/integrations/<kebab-name>.ts`.** Вимоги до коду — у
   `.claude/rules/architecture.md` і `.claude/rules/conventions.md`; не переписуй
   їх сюди, звіряйся з файлами. Використовуй **лише** ті експорти ядра, що
   перелічені в `architecture.md`.

5. **Створи `app/src/integrations/<kebab-name>.test.ts`** — поруч, із трьома
   випадками: успішна відправка з перевіркою **URL і тіла запиту**, відсутня
   змінна середовища, помилка від зовнішньої системи. Реальної мережі в тестах
   немає. Для сповіщення додай четвертий випадок: у тілі немає email і телефону.

6. **Додай рівно один рядок імпорту й один елемент масиву** в
   `app/src/integrations/index.ts`. Більше в цьому файлі не міняй нічого.

7. **Перевір** і винеси числа в підсумок:
   ```
   cd app && npm test
   cd app && npm run typecheck
   cd app && npm run check:rules
   ```

8. **Підсумок:** перелік створених і змінених файлів, назва й `requiredEnv`
   інтеграції, тип системи з кроку 3, і числа з кроку 7.

## Acceptance criteria

- [ ] Створено рівно два нові файли: `<kebab-name>.ts` і `<kebab-name>.test.ts`,
      обидва в `app/src/integrations/`.
- [ ] Змінено рівно один наявний файл — `app/src/integrations/index.ts`, і в ньому
      додано один рядок імпорту й один елемент масиву. Перевіряй **діфом, а не
      очима**: `git diff --numstat -- app/src/integrations/index.ts` має дати
      рівно `2	1` — два доданих рядки (імпорт і переписаний рядок масиву) і
      один видалений (старий рядок масиву). Будь-які інші числа означають, що
      в реєстрі зачепили щось іще.
- [ ] `git status --short` не показує жодного іншого створеного чи зміненого файлу.
- [ ] Поле `name` дорівнює імені файлу без розширення.
- [ ] `requiredEnv` містить лише імена змінних. Значень секретів у репозиторії
      не з'явилось — перевіряй **вмістом, а не `git diff`**: нові файли не
      відстежуються, і `git diff` їх не бачить. Команда:
      `grep -nE "(xox[abp]-|sk-|ghp_|bot[0-9]{6,}:|Bearer [A-Za-z0-9])" app/src/integrations/<kebab-name>.ts app/src/integrations/<kebab-name>.test.ts`
      → порожньо.
- [ ] У тесті є всі три обов'язкові випадки; для сповіщення — і четвертий,
      що перевіряє відсутність email і телефону в тілі.
- [ ] **У новому `*.test.ts` немає `console.`, `process.env`, `: any` / `as any`
      і жодного значення секрету** (середовище підміняй через `vi.stubEnv`).
      `check:rules` файли `*.test.ts` **не сканує**
      (`app/scripts/check-rules.mjs:100`, фільтр `!name.endsWith(".test.ts")`),
      тож цей пункт перевіряють очима, а не командою.
      `JSON.parse` немає і в тесті: перехоплене тіло розбирай через
      `parseJson` з guard, як вимагає конвенція 4 — винятку для тестів немає.
- [ ] `cd app && npm test` зелений; **усі** нові тести зелені, і число тестів
      зросло щонайменше на 3 (для сповіщення — на 4). Більше — добре:
      верхньої межі немає.
- [ ] `cd app && npm run typecheck` зелений.
- [ ] `cd app && npm run check:rules` → `TOTAL` **не зріс** проти стану до команди,
      і в новому модулі нуль порушень. Числа зняті звичайним прогоном;
      `--write-lock` не запускався.
- [ ] `app/package.json` не змінено; ключа `dependencies` не з'явилось; код
      сторонньої бібліотеки не скопійовано в модуль.
- [ ] Жоден файл із `.claude/rules/do-not-touch.md` не змінений.

## Stop

Зупинись і спитай людину, **не роблячи зміни**, якщо справджується будь-що з цього:

- потрібного експорту немає в публічному API ядра — не додавай його в `core/`
  і не роби власну копію функції ядра в `integrations/`;
- у `Lead` немає поля, якого вимагає сервіс — не розширюй тип, **не оголошуй в
  `integrations/` власний інтерфейс, що дублює чи розширює `Lead`**, і не обходь
  його через `any` чи приведення типу;
- сервіс не лягає в контракт `Integration` (потрібен не `send(lead)`, а щось інше);
- без нової бібліотеки не обійтись;
- знадобився третій файл або підтека.

Опиши, що саме заблокувало, у якому файлі й рядку потрібна зміна, і чекай відповіді.

Після успішного створення теж зупинись: покажи підсумок із кроку 8 і **не
переходь** до наступних інтеграцій, реєстрації в `sync/`, документації чи коміту,
доки людина не скаже.
